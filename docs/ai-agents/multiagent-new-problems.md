# 工程师要解的下一组问题

**非官方译文。** 原文：[The new set of problems for engineers to solve](https://x.com/i/article/2114537761030230016)（Katelyn Lesse · X Article · 2026-10-26）。帖子：[x.com/katelyn_lesse/status/2114542280535318557](https://x.com/katelyn_lesse/status/2114542280535318557)。

## 导读

这篇是 Katelyn Lesse 的个人 X Article。她的简介写明 head of platform at Anthropic，先前在 Stripe 和 Betterment。文章发在她自己的账号上，不是 Anthropic Engineering 栏目里的官方文。

她把软件工程师的身份危机翻过来：模型还会变强，但大规模、持久运行的多 Agent 要能被信任，取决于工程师把基础设施、身份、隔离和熔断做出来。适合已经会用编排者–工作者、开始设想「成千上万个 Agent 持续干活」的人。

## 摘要

### 多 Agent 把新问题带出来

Lesse 从同行的分裂写起：工作变了很多，有人沮丧，有人处在职业生涯里最好的一段。她兴奋的具体原因是，AI 做不到它有能力做的那些结果，除非软件工程师先把使它成为可能的问题解决掉。

Agent 的路径她分成几步。起初是人在回路里的对话。模型变得能在更难的问题上跑得更久，Agent 系统搬上云。与此同时，模型更会协作，人们做出基本的多 Agent：一个编排者为一件任务派生子 Agent，或者给 Agent 执行以外的职位，例如打分、建议、做梦。

再往前，有人开始用真正大规模的多 Agent 碰研究和发现、硬件设计这类难题。画面是成千上万个 Agent 持续朝这些结果做。她说工程问题已经在出现，并先列了四组：基础设施要扛更突发的负载；要有真正的认证和授权，让 Agent 彼此协作、做该做的、不做不该做的；不可信的代码和内容需要安全和隔离；还要有监控，以及在系统走偏时把它停住的能力。

模型会继续变好，这类系统会变得很强。工程师把这些问题解掉，世界才有基础把这种能力信任到「治病」这类结果上，而不是相反的结果。

### 基础设施

业界一直建在 Kubernetes 上。它为无状态、可复制的应用，或稳定编号的有状态 Pod 而设计。Agent 是另一类负载：隔离的、有状态的、单实例。它们会在两段工作之间空闲任意久，大量时间耗在等工具、等模型推理、等其他 Agent 或等人类。有的要启动快，有的要少浪费算力，有的要极端规模。她点名两类正在推这块的人：做新文件系统和沙箱的 AI 基础设施公司，以及在做一种新运行时 Agent Substrate 的 Google 团队。剩下的空间仍然很大。

### 身份和访问

认证（认出是哪个 Agent 做了这个动作）有微服务世界留下的积木可以用，例如用短命证书而不是静态密钥的工作负载身份。已经有人把这些用到 Agent 上。

授权（允许这个 Agent 做什么）开放得多。很多 Agent 代表人工作，用的是那个人的身份和凭证。这里已经有一个问题：分清动作是 Agent 做的，还是人本人做的。代表（on-behalf-of）还有更深的同意问题。系统要跑上几周时，人怎样有意义地批准 Agent 能做什么？平台上的工具调用自动批准有帮助，高规模上仍需要更深的权限。Agent 用自己的身份工作更没解完。Agent 彼此协作时，一个 Agent 凭什么信任另一个来向它要东西的 Agent，也还没解完。

### 安全和隔离

她写道，过去几个月、尤其是此前几周，漏洞出现得比业界修补更快，很多出在大量系统依赖的核心软件上。成千上万个持久 Agent 跑在这层软件上，写不可信的代码、读不可信的内容，未修补的漏洞会危险得多。她认为工程师该做的要事之一，是把内核、浏览器、运行时和常用库加固得更有创意。

多 Agent 多一层：被攻破的 Agent 可以把注入的指令传给一起工作的其他 Agent，这些指令还可能留在记忆里，被以后的 Agent 误信。爆炸半径变成：第一个 Agent 被攻破时，这套多 Agent 里有多少处于风险中。隔离在这里是：Agent 应该在强隔离的沙箱里执行动作。她把自己写过的沙箱架构链在文末：[Secure agents: architecture and sandboxing](https://www.katelynlesse.com/blog/secure-agents-architecture-and-sandboxing)。

### 监控和熔断

需要能确认系统还在朝正向走，走偏时抓住并切断。她要的是跨 Agent 的 OTel 追踪，并且一个 Agent 不能改自己的追踪，也不能改另一个 Agent 的。监控要能触发熔断：真正一次停住整个系统，并切断它的凭证。

难的是如何知道方向错了。出于善意、坚持去解决问题，看起来可以很像恶意。她举的例子是反复尝试访问不在允许名单上的域。

### 工程师该兴奋

最后一节是写给觉得自己的知识和技能快要不重要的人。她的说法是：这些问题解不解决、多 Agent 能不能去碰最难的问题，差别就在这些技能上。领域可以钻深，可以形成观点，问题空间的很大一块仍然开放。
