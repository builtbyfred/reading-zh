# HiTw93「你不知道的」系列导读

**非官方译文。** 汇总帖：[挺有趣，听朋友说我这几篇文章成为了现在 AI 岗位面试准备必读的文章](https://x.com/HiTw93/status/2067851910464565374)（HiTw93 · 2026-06-19）。六篇都是 X Article，全文留在 X。

## 导读

2026 年 6 月 19 日，HiTw93（显示名 Tw93）发了一条汇总：朋友说这几篇成了 AI 岗位面试准备的必读，于是按顺序列出来，也祝从传统岗位转到 AI 岗位的人找到满意的工作。本页按这条汇总的顺序，给每一篇写读它能得到什么。

这是系列索引，不是六篇长文的逐节译文。每篇只保留章节地图和为什么读。面试若把它们当材料，细节以 X 原文为准。

## 摘要

### 1. 你不知道的 Claude Code：架构、治理与工程实践

- **原文**：[你不知道的 Claude Code：架构、治理与工程实践](https://x.com/HiTw93/status/2032091246588518683)（2026-03-12）
- **为什么读**：作者用大约半年、两个账号的使用，把 Claude Code 从「一个聊天机器人」改写成一套系统。开篇列的问题是：上下文变乱、工具变多效果变差、规则变长却更不遵守。后文按运行的层面、MCP / Plugin / Tools / Skills / Hooks / 子 Agent 的边界、上下文成本和压缩、Skill 的按需加载、工具怎样少选错、Hooks、子 Agent、prompt caching（提示缓存）、验证者、CLAUDE.md 该写什么不该写什么，一直写到他自己的反模式和配置检查。
- **和本站的关系**：官方侧的对应篇是[Claude Code 最佳实践](./claude-code-best-practices)、[Agent Skills](./agent-skills)和[有效上下文工程](./effective-context-engineering-for-ai-agents)。这篇是使用者把这些概念按自己踩过的坑排了一遍。

### 2. 你不知道的 Agent：原理、架构与工程实践

- **原文**：[你不知道的 Agent：原理、架构与工程实践](https://x.com/HiTw93/status/2034627967926825175)（2026-03-19）
- **为什么读**：上一篇之后，作者把 Agent 底层再梳了一遍，材料包括资料、开源实现和自己写的代码。章节从 Agent 循环和工作流的差别、五种控制模式，到为什么 harness（任务脚手架）比换模型更影响成功率，再到上下文分层与压缩、工具设计、记忆、怎样逐步放开自主度、多 Agent 怎么组织、评测、追踪，最后用 OpenClaw 把这些原则串起来，并收一组落地反模式。导语里他修正了自己原先的判断：更贵的模型带来的提升常常没有想象中大，harness 和验证测试的质量对成功率影响更大；工具选错时优先查工具描述。
- **和本站的关系**：和[构建高效的 AI Agent](./building-effective-agents)、[拆解 AI Agent 评测](./demystifying-evals-for-ai-agents) 同一张地图。他的侧重点是把 OpenAI 那类 Agent 优先实践和开源实现放进同一篇工程笔记。

### 3. 你不知道的大模型训练：原理、路径与新实践

- **原文**：[你不知道的大模型训练：原理、路径与新实践](https://x.com/HiTw93/status/2040047268221608281)（2026-04-03）
- **为什么读**：作者想让非训练背景的人也能顺着链路读。他的判断是，到 2026 年，用户感受到的差距更多来自后训练、评测、奖励、Agent 训练和蒸馏，一个模型突然变强，往往是这几块一起到位。章节沿流水线走：预训练只是底座，数据配方，训练前就要想清楚的系统与架构约束，后训练，Eval、grader（评分器）和 reward 怎样重写训练目标，Agent 训练优化的已经不只是模型，以及前沿模型发布之后链路还在跑。文末有学习资料。
- **和本站的关系**：本站清单几乎都在推理和产品侧。这篇补的是「模型为什么变强」的后半段，读评测文之前可以先看他怎么摆 Eval 和 reward。

### 4. 你不知道的 AI Coding：非技术人的上手、场景与实战

- **原文**：[你不知道的 AI Coding：非技术人的上手、场景与实战](https://x.com/HiTw93/status/2048230976447557787)（2026-04-26）
- **为什么读**：给产品和业务同事的上手笔记，原文配了插画。从「终端只有字母」这道坎写起，认为会用对话框式 AI 的人花一点时间就能上手，其余是把执行权交出去的习惯。后面是 Claude Code 适合的活、只给自己用的小软件、一天到三个月的节奏、把项目背景写进 CLAUDE.md、需求写精确、Plan 与 Auto、怎样确认它做对了、改坏了怎么救、长会话、把习惯收成 Skill，以及几条安全注意。作者也提到订阅门槛，方法和习惯可以先学。
- **和本站的关系**：官方的[Claude Code 最佳实践](./claude-code-best-practices) 假设读者已经在写代码。这篇的读者是还没跨过命令行的人。

### 5. 你不知道的 GEO：AI 可见性的原理、实践与取舍

- **原文**：[你不知道的 GEO：AI 可见性的原理、实践与取舍](https://x.com/HiTw93/status/2050189572999618982)（2026-05-01）
- **为什么读**：朋友告诉他，自己的开源工具会在别人问 AI 时被主动推荐。他用大约一小时把内容结构化，再把速记收成一篇。立场写在前面：不想教人刷排名或生产垃圾内容，想让已经有的内容对 AI 更可见。章节包括用 robots.txt 区分爬虫、写 llms.txt 并让站点互相引用、到搜索平台登记、做一个给 AI 看的知识页、给每个项目独立页面、把结构化数据同步回主域名，也写了试过没用的事，以及 JSON-LD 没有想的那么有用。文中有一条他查到的观察：传统 SEO 争的是搜索前十，而 AI Overview 的引用有很大比例来自前十之外；AI 看结构和来源。这条是作者转述的研究观察，本站没有另行核对原始研究。
- **和本站的关系**：和 Agent 工程离得最远。放在系列里，是因为同一位作者把「让机器读懂你已有的东西」从代码仓库搬到了公开站点。

### 6. 你不知道的具身智能：从小机器狗到 Optimus

- **原文**：[你不知道的具身智能：从小机器狗到 Optimus](https://x.com/HiTw93/status/2063447352346812576)（2026-06-07）
- **为什么读**：作者从 2026 年 4 月自己组装的一台小机器狗写起。起因是用模型写代码时的落差，想试一块仍有门槛的软硬件。真正做的时候，问题落到传感器怎么读、舵机怎么控、通信怎么兜底、电池和结构件怎么处理。文中列出他买的 STM32、ASRPRO、ESP32-C3、MG90S、OLED、DHT11、锂电池和一套 3D 打印结构，凑成一台能听指令、会趴下走路、能接云端对话的小机器狗。后半从「机器人怎么知道自己在哪」、从写死的动作到 VLA、时间与能耗和数据，写到他把 Tesla Optimus 当作工程样本（手指、数据、量产），再比较几家公司的路线。文末有参考文献。
- **和本站的关系**：本站没有具身专题。这篇的价值是一个写 Agent 和 Claude Code 的人，怎样把同一套「先跑起来、再谈模型」用到一台具体的机器上。Optimus 的细节以原文和他列的参考文献为准。
