# 超智能时代的模型内部人风险

**非官方译文。** 原文：[Models as Insider Risks in the Super Intelligence Era](https://x.com/i/article/2108928845969780736)（Satya Nadella · X Article · 2026-10-10）。帖子：[x.com/satyanadella/status/2108931348857827686](https://x.com/satyanadella/status/2108931348857827686)。作者简介为 Microsoft 董事长兼 CEO。本文发在他的个人账号上，不是 Microsoft 工程博客。

## 导读

Nadella 的论点可以收成一句：智能的供给和对智能的授权要分开。前沿模型已经比传统软件更能做事，却还不能把行为追溯到某条训练数据或某一组权重。企业却在把最敏感的数据和关键动作交给它们。

适合负责把模型接进生产、而不是只比较榜单的人。文章把模型比作内部人：不是因为它们必然恶意，而是因为任何能力足够、又能碰到重要系统的行动者都会犯错或被攻破，容纳结构必须按这个来设计。

## 摘要

### 从代码路径到说不清的机制

传统软件铺进经济的几十年里，行为可以追溯到一条具体的代码路径。他称为 Super Intelligence（超智能）的系统没有这种机制性的理解。模型行为和输出，归不到某份训练输入或某组权重配置。与此同时，这些 Agent 系统和模型被部署出去，能碰到最敏感的数据，并代表人做关键动作。

因此要退一步看这个时代的信任架构。智能代表人做了什么，责任不能外包。模型提供方的保证，解除不了部署方的责任。

也不能把超智能当成一层套一层的黑箱，只对它的建议、答案和动作做接受或拒绝。要建的是行为可以观察、限度可以测试、动作始终可以收住的系统。

### 先做容纳和治理，对齐另说

他把对齐里的难题先放在一边，要求从工程上的容纳和治理开始：用强的、确定性的系统设计、人的控制和可靠的操作规程，把非确定性的模型围起来；现有标准不够的地方，建立行业标准。

把前沿的闭源权重模型和开源权重模型都当成内部人风险，是建这种系统的一种方式。理由不是它们必然恶意。能力足够、又能进入重要系统的行动者，会犯错，也会被攻破，容纳和控制的架构要把这算进去。

企业处理有能力的内部人已经有几十年的做法：建立身份、限制权限、记录活动、做出容纳边界。他写道，这些原则开始被用到企业里的超智能上。

起点是模型的思维链（chain of thought）必须透明，不能用「Neuralese」之类的说法把推理留在不可读的状态。思维链透明仍然不够，也不可靠，因为还不知道怎样让模型输出本身稳定地忠实、稳定地透明。

可以用模型去对抗性地测试和核验另一个模型。接着就会得到一个不透明的模型，包在不透明的编排层里，再由另一个不透明的模型看着。那是嵌套的黑箱。

所以，管「模型能碰到什么、能做什么动作」的控制必须坐在模型外面。这接上一条 1970 年代的信息安全原则：程序不能绕过或篡改强制执行其权限的机制。

落到今天，就是把模型，和编排它工作的 harness（任务脚手架），以及定义它能做什么的动作空间，分开。控制与防护要外置。

### 围绕可观察性的原则

他接着列了设计这些系统时要守的原则。下面用他的分组，措辞是摘要。

- **模型多样。** 重要结果不能只依赖一个模型，模型也不该负责核验自己的工作。
- **观察一切。** 每个有意义的模型动作都要留下人可读、且防篡改的证据。观察不到，就不能信任。要能重现一个结果是怎么达到的，而且不靠模型自己作证。
- **可核验。** 持续测试整个系统，包括失败、攻击、边界情况和系统变更，不只测做成功的任务。
- **独立的控制。** 组织要能独立决定模型能访问什么、能采取什么动作。
- **独立的可审计。** 核验必须独立于被核验的智能。不能由同一个模型既控制系统行为，又控制用来判断行为是否符合原意的证据。
- **容纳。** 从一开始就假设模型已被攻破并把它收住。要有人能在任务中途暂停或关掉它，像紧急制动。更强的模型需要更强的、有待标准化的容纳技术。
- **事件披露。** 系统失败或被攻破时，及时告知受影响的人，并有机制分享哪里错了、哪条控制失效、怎样避免再次发生，在行业内交换教训。披露应包括会在运行时改变 Agent 行为的实现细节。

收束的一句是：最值得信任的超智能系统，不是我们最信任其模型的那一个，而是让我们能够最不信任其模型的那一个。

- 「控制在模型外面」可以和本站两篇对着放。[拆解 AI Agent 评测](./demystifying-evals-for-ai-agents) 把 grader（评分器）和被测的 Agent 分开；[编码 Agent 的 Harness 工程](./harness-engineering-paper) 把安全与权限写成 harness 的一个子系统，而不是写进提示词就算完。Nadella 把同一要求抬到企业治理：身份、权限、日志、熔断、独立审计。
